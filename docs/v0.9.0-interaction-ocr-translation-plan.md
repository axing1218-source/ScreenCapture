# WeShot v0.9.0 Interaction / OCR / Translation Plan

This document refines the v0.9.0 core plan around the three user-facing flows that must behave as one coherent screenshot tool: WeChat-like capture interaction, the OCR side panel, and in-place translation.

## 1. Capture interaction contract

- The screenshot selection remains the single source of truth for the active capture region.
- Opening OCR, translation, or annotation must not resize, move, or implicitly commit a new selection.
- The OCR side panel owns pointer input from mouse-down through mouse-up while the pointer is inside the panel; events must not leak back into selection adjustment.
- Original/Translated is a local display toggle after the first successful translation. It must not send another network request.
- Moving or resizing the selection immediately hides stale translated pixels. A new capture revision is committed once on mouse-up only when the rectangle really changed.
- Async OCR/translation results are accepted only when both the capture revision and UI lifetime token still match.

## 2. Shared capture session

A `CaptureSession` should be owned by the active capture window and shared by toolbar translation and the OCR side panel.

Minimum state:

- immutable BGRA snapshot for the committed selection
- physical-pixel size and absolute virtual-screen origin
- monotonically increasing capture revision
- OCR line boxes and recognized source text
- paragraph/layout boxes and reading order
- translated text keyed by layout region
- Original/Translated render cache
- in-flight OCR/translation state

The side panel may close without destroying the session. Reopening it for the same revision should reuse OCR/layout/translation results.

## 3. OCR side panel

The side panel should stay lightweight and behave like a view over the shared session, not a second OCR pipeline.

- Left side: captured image with optional OCR/layout debug overlays during development.
- Right side: selectable text with `Original / Translation` tabs.
- Text selection, wheel scrolling, Ctrl+A and Ctrl+C are consumed by the panel.
- Switching tabs updates both the right-side text and the left-side rendered image from local cache.
- If OCR is already available for the current revision, opening the panel is instant.
- If OCR is pending, show explicit state without blocking screenshot interaction.

## 4. Geometry ownership

Physical geometry must come from local OCR/text detection, not Gemini.

Pipeline:

`capture snapshot -> OCR line boxes -> line normalization -> paragraph/layout grouping -> language routing -> translation -> local render`

The layout engine should preserve:

- title vs body scale
- paragraph grouping
- list/chat/UI regions
- reading order
- source alignment where practical

A geometry validation pass rejects overlaps, boxes outside the capture bounds, and implausible paragraph merges before translation is rendered.

## 5. Gemini role

Gemini is responsible for translation and semantic disambiguation only.

Preferred request path when local OCR is reliable:

`recognized source regions + reading order + target language -> translated regions`

Only fall back to image-assisted Gemini translation when local OCR confidence/coverage is insufficient. This avoids paying vision latency for every translation and prevents Gemini geometry drift.

Transport and model tuning are separate from layout quality. Do not mix timeout/proxy changes with OCR/layout experiments in one release gate.

## 6. WeChat-like in-place rendering

Rendering is local and reversible.

1. Start from the immutable original snapshot.
2. For each translated layout region, estimate background from pixels around the text boundary rather than averaging the whole box.
3. Remove source glyphs using local background reconstruction/inpainting appropriate to the region.
4. Use source typography as the baseline: preserve approximate size, weight, alignment and text color.
5. Fit translated text with DirectWrite; shrink only when needed, never enlarge short translation merely to fill the source box.
6. Validate that translated regions do not overlap or overflow.
7. Cache the translated bitmap for instant Original/Translated toggling.

## 7. Implementation gates

### Gate A — shared capture identity

Introduce `CaptureSession`, immutable snapshot and revision semantics. Migrate toolbar translation and OCR panel to the same snapshot source.

### Gate B — OCR/layout prototype

Keep the prototype isolated from production translation. Acceptance target: stable line boxes and stable paragraph/layout boxes on a fixed difficult screenshot benchmark set.

### Gate C — side panel integration

Use session OCR/layout data, enforce full pointer/keyboard input isolation, and make reopening the panel cache-only for an unchanged revision.

### Gate D — Gemini translation integration

Translate local text regions without asking Gemini for physical coordinates. Reuse one in-flight request per revision/target-language pair.

### Gate E — local translated bitmap

Implement background reconstruction, DirectWrite fitting, layout validation and instant local Original/Translated switching.

## 8. Test matrix

Every test build should include the same regression set:

- small English UI text
- mixed Chinese/English text
- title + paragraph + list
- chat bubbles / messaging UI
- dark and light backgrounds
- gradients or textured backgrounds
- 100% / 150% mixed-DPI monitors
- negative-coordinate secondary monitor
- resize selection while OCR/translation is pending
- open/close/reopen OCR panel without changing the selection

Measure OCR coverage, geometry stability, first translation latency, translated overflow/overlap count, and whether a second Original/Translated toggle performs zero network requests.
