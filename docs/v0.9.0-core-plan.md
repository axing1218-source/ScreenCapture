# WeShot v0.9.0 Core Plan

This branch starts the post-v0.8.x architecture work. The goal is to stop treating Gemini-generated geometry as the source of truth for screenshot translation.

## Foundation

- Central user-facing version: `v0.9.0`.
- Windows file/product version follows the WeShot version instead of upstream ScreenCapture 2.5.x.
- Configurable clipboard-window shortcut, default `Ctrl+Alt+V`.
- Clipboard shortcut is a toggle: visible -> hide; hidden -> show.

## Translation core target

1. Dedicated local OCR/text detection produces physical text-line geometry.
2. A screenshot-specific layout engine groups lines into titles, paragraphs, lists, chat/UI regions and reading order.
3. Language routing decides per region whether to preserve or translate.
4. Gemini is used for translation/semantics, not for physical layout geometry.
5. DirectWrite renders into protected paragraph slots using source typography as the baseline: keep source-like size when it fits, shrink only when necessary, never enlarge short translations merely to fill space.
6. Final layout validation rejects overlap and overflow.

## OCR prototype policy

The first OCR prototype should be isolated from the production translation path. Its first success criterion is only:

`image -> stable OCR line boxes -> stable paragraph/layout boxes`

Translation is integrated only after geometry passes the difficult screenshot benchmark set.

## Clipboard research policy

The existing v0.8.15 clipboard window is only a session-memory prototype. The redesign should study uTools/Super Clipboard and other mature clipboard managers before changing the UI/data model. Likely core ideas to validate include content-hash deduplication, search, pin/favorite, keyboard-first selection/paste, rich previews, privacy/pause controls and optional local persistence.
