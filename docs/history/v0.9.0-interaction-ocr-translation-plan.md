# WeShot v0.9.x Interaction / OCR / Translation Plan

This document tracks the screenshot/OCR/translation work on the current `weshot-v0.9.1-clipboard` branch (application version v0.9.3). Clipboard work is allowed to continue independently, but screenshot interaction, OCR and Gemini translation must share one coherent capture-state model.

## 0. Current baseline audit

The current branch still contains the older Gemini transport behavior in `Src/GeminiClient.h`: Flash requests may select `minimal`, real inference uses a 25-second receive timeout, send and wait-response failures are collapsed into one generic error, and the connection test performs a generation request that asks the model to return `OK`.

Before changing OCR geometry or translation rendering, stabilize this transport path as an isolated gate:

- keep the currently selected Gemini model and existing WinHTTP automatic-proxy path
- use a supported low-latency thinking configuration (`low` for Gemini 3.x Flash)
- separate connect/send/wait-response/read/HTTP/parse failures in diagnostics
- use a realistic inference receive ceiling (60 seconds) so slow inference is not misreported as loss of connectivity
- make `Test connection` a lightweight model-metadata request rather than model inference
- log only timings/status/error codes; never log API keys, screenshot bytes, OCR text, translations or request bodies

Transport changes must ship in their own build gate. Do not mix them with OCR geometry, image-resolution A/B tests, proxy experiments or rendering changes.

## 1. Capture interaction contract

- The screenshot selection remains the single source of truth for the active capture region.
- Opening OCR, translation, annotation or clipboard UI must not resize, move or implicitly commit a new selection.
- The OCR side panel owns pointer input from mouse-down through mouse-up while the pointer is inside the panel; events must not leak back into selection adjustment.
- Text selection, wheel scrolling, Ctrl+A and Ctrl+C inside the OCR panel are consumed by the panel.
- Original/Translated is a local display toggle after the first successful translation. It must not send another network request.
- Moving or resizing the selection immediately hides stale translated pixels. A new capture revision is committed once on mouse-up only when the rectangle really changed.
- Async OCR/translation results are accepted only when both the capture revision and UI lifetime token still match.

## 2. Shared capture session

A `CaptureSession` should be owned by the active capture window and shared by toolbar translation and the OCR side panel.

Minimum state:

- immutable BGRA snapshot for the committed selection
- physical-pixel size and absolute virtual-screen origin
- monotonically increasing capture revision
- OCR line boxes and recognized source text
- paragraph/layout boxes and reading order
- translated text keyed by layout region and target language
- Original/Translated render cache
- in-flight OCR/translation state
- cancellation/lifetime token for asynchronous callbacks

The side panel may close without destroying the session. Reopening it for the same revision must reuse OCR/layout/translation results. The session must be invalidated only by a committed capture change, not by opening or closing UI.

## 3. OCR side panel

The side panel is a view over the shared session, not a second OCR pipeline.

- Left side: captured image with optional OCR/layout debug overlays during development.
- Right side: selectable text with `Original / Translation` tabs.
- Switching tabs updates both the right-side text and the left-side rendered image from local cache.
- If OCR already exists for the current revision, opening the panel is instant.
- If OCR is pending, show an explicit non-blocking state.
- Closing/reopening the panel must not restart OCR for an unchanged revision.
- The panel must never hold raw pointers that an async callback can access after the panel closes.

## 4. Geometry ownership

Physical geometry comes from local OCR/text detection, not Gemini.

Pipeline:

`capture snapshot -> OCR line boxes -> line normalization -> paragraph/layout grouping -> language routing -> translation -> local render`

The layout engine should preserve:

- title vs body scale
- paragraph grouping
- list/chat/UI regions
- reading order
- source alignment where practical
- physical-pixel coordinates across mixed-DPI and negative-coordinate monitors

A geometry validation pass rejects overlaps, boxes outside capture bounds and implausible paragraph merges before translated rendering begins.

## 5. Translation request routing

Gemini is responsible for translation and semantic disambiguation, not physical text geometry.

Preferred route when local OCR coverage is reliable:

`recognized source regions + stable region IDs + reading order + target language -> translated regions`

Use one in-flight translation request per `(captureRevision, targetLanguage)` and let toolbar translation and the OCR panel attach to the same result.

Fallback to image-assisted translation only when local OCR coverage/confidence is insufficient. Image fallback must still map returned translations onto locally owned region IDs whenever possible; Gemini coordinates are advisory fallback data, not the primary geometry source.

This routing gives three latency tiers:

1. cached translation: zero network
2. local OCR already available: text-only translation request
3. insufficient local OCR: image-assisted Gemini request

## 6. WeChat-like in-place rendering

Rendering is local, reversible and never asks Gemini to generate an edited screenshot.

1. Start from the immutable original snapshot.
2. For each translated layout region, sample background around the outside boundary rather than averaging the entire text box.
3. Remove source glyphs using local reconstruction/inpainting appropriate to the region.
4. Estimate source text color and preserve approximate font size, weight and alignment.
5. Fit translated text with DirectWrite. Shrink only when necessary; do not enlarge short translations merely to fill the original box.
6. Validate translated regions for clipping, overlap and excessive shrink.
7. Cache the final translated bitmap so Original/Translated toggling is immediate and network-free.

For the first renderer milestone, prefer robust flat/near-flat background reconstruction. Complex gradients/textures can use a later inpainting path rather than blocking the basic WeChat-like workflow.

## 7. Implementation gates

### Gate T — Gemini transport stabilization

Complete and regression-test the isolated transport changes from section 0 before touching OCR/layout/rendering.

Acceptance:

- valid key/model check returns quickly without inference
- invalid key returns HTTP/API error, not generic timeout
- send and wait-response failures are distinguishable
- inference can legitimately run beyond 25 seconds without being killed by the client
- no sensitive request data is written to diagnostics

### Gate A — shared capture identity

Introduce `CaptureSession`, immutable snapshot and revision semantics. Migrate toolbar translation and OCR panel to the same snapshot source.

Acceptance:

- same selection => same revision/snapshot for toolbar and OCR panel
- moving/resizing commits exactly one new revision on mouse-up
- stale async results are discarded
- mixed-DPI / negative-coordinate monitor geometry remains correct

### Gate B — OCR/layout integration

Use the current local OCR path to produce stable line boxes and paragraph/layout regions. Keep OCR benchmarking independent from Gemini model tuning.

Acceptance:

- stable region IDs for the same screenshot
- small UI text and mixed Chinese/English remain readable
- paragraph grouping is deterministic enough to reuse translations by region ID

### Gate C — side panel integration

Use only session OCR/layout data, enforce full pointer/keyboard input isolation, and make reopening the panel cache-only for an unchanged revision.

### Gate D — translation request reuse

Translate local regions without asking Gemini for primary physical coordinates. Reuse one in-flight request per revision/target-language pair across toolbar and OCR panel.

### Gate E — local translated bitmap

Implement boundary background sampling, source-glyph removal, DirectWrite fitting, layout validation and instant local Original/Translated switching.

## 8. Test matrix

Every test build should use the same regression set:

- small English UI text
- mixed Chinese/English text
- title + paragraph + list
- chat bubbles / messaging UI
- dark and light backgrounds
- gradients or textured backgrounds
- 100% / 150% mixed-DPI monitors
- negative-coordinate secondary monitor
- resize selection while OCR/translation is pending
- open/close/reopen OCR panel without changing the selection
- trigger toolbar translation and OCR-panel translation nearly simultaneously

Measure:

- OCR text coverage
- geometry/region-ID stability
- connection-test latency
- first translation latency
- whether text-only translation was used when OCR already existed
- duplicate Gemini request count per revision
- translated overflow/overlap count
- whether every subsequent Original/Translated toggle performs zero network requests

## 9. Release discipline

Each gate gets its own Windows x64 build. A gate is not combined with the next one merely because CI is green. Keep one behavioral variable per test build so regressions can be attributed quickly.

The clipboard redesign on the current branch is treated as orthogonal: screenshot/OCR/translation code must not depend on clipboard-history window lifetime, and clipboard UI must not capture or leak screenshot selection input.
