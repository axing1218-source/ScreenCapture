# WeShot v0.9.5 Screenshot / OCR / Translation Refinement

This note refines the existing v0.9.x interaction/OCR/translation plan against the current `weshot-v0.9.1-clipboard` branch, whose latest work now includes the v0.9.5 clipboard rail patch chain.

## 1. Integration guardrail

Clipboard UI work and screenshot/OCR/translation work must remain source-level independent. The current clipboard branch applies a chain of PowerShell patches at build time; screenshot/OCR/translation changes should not add more build-time patching to `WinCap`, OCR or Gemini code. New screenshot/OCR/translation behavior should land directly in production source so CI validates behavior instead of manufacturing it.

This avoids three failure modes:

- patch ordering silently overwriting screenshot state or input routing changes
- a successful build producing different behavior from the checked-in C++ source
- clipboard-window lifetime accidentally becoming a dependency of capture/OCR callbacks

## 2. Immediate gate order

### T1 — Gemini transport only

Change only `Src/GeminiClient.h`:

- replace unsupported Flash `minimal` thinking with `low`
- raise real inference receive timeout from 25 s to 60 s
- split send and wait-response failures, retaining Windows error code and elapsed time
- make `Test connection` use model metadata (`GET /v1beta/models/{model}`) instead of inference
- keep the existing WinHTTP automatic-proxy path and current model selection
- do not change image resolution, OCR geometry, renderer or API family in this gate

Acceptance: a slow request can exceed 25 s without false timeout; invalid key returns an HTTP/API error; diagnostics distinguish send vs wait-response; no request body, API key, screenshot or OCR text is logged.

### A1 — Shared capture identity

Add one capture-owned session containing an immutable committed-selection snapshot, physical-pixel bounds/origin, monotonically increasing revision and lifetime token.

Rules:

- first committed selection receives a valid revision before command-line OCR or toolbar early-return paths
- drag/resize does not increment while moving; mouse-up increments exactly once only if the committed rectangle changed
- opening/closing OCR, toggling Original/Translated, clipboard UI and annotations do not change revision
- stale async results require both matching revision and live UI/session token

### B1 — OCR side panel as a view

The OCR panel must consume session OCR/layout data instead of owning a second recognition pipeline. Pointer input is captured from mouse-down through mouse-up while inside the panel so text selection, wheel scrolling and Ctrl+A/C cannot leak into screenshot selection adjustment.

### C1 — Shared translation request graph

Use one in-flight translation per `(captureRevision, targetLanguage)`. Toolbar translation and OCR-panel translation attach to the same future/result. When local OCR/layout coverage is sufficient, send region IDs + text only; fall back to image-assisted translation only when necessary.

### D1 — WeChat-like local rendering

Gemini supplies semantics, not edited pixels. WeShot locally reconstructs each source-text region, estimates background/text appearance, fits translated text with DirectWrite and caches the translated bitmap. Original/Translated toggling after the first completion is always local and network-free.

## 3. State contract

Use one shared state machine rather than independent toolbar/panel booleans:

`Original -> OCRPending -> OCRReady -> TranslationPending -> TranslationReady`

`Error` is recoverable without changing capture revision. A new committed selection invalidates OCR, translation and translated-bitmap caches and returns to `Original` under a new revision.

During `TranslationPending`, moving/resizing the capture immediately hides any old translated bitmap. Completion for an older revision is discarded silently except for optional diagnostic counters.

## 4. Performance instrumentation

Record only non-sensitive timing counters per request:

- PNG encode time (image-assisted route only)
- request construction time
- send time
- wait-response time
- response-read/parse time
- local render time
- route used: cached / text-only / image-assisted

The UI should report one user-facing first-translation elapsed time, while detailed stage timings remain diagnostic-only.

## 5. Test build discipline

Do not combine T1 with capture-session or renderer changes. Produce a Windows x64 build after each gate. The fixed regression set is:

- small English UI text
- mixed Chinese/English
- title + paragraph + list
- chat bubbles
- dark/light background
- mixed 100%/150% DPI monitors
- negative-coordinate secondary monitor
- selection resize while OCR/translation is pending
- OCR panel close/reopen on unchanged selection
- near-simultaneous toolbar and panel translation

Primary counters: first translation latency, duplicate Gemini requests per revision, stale-result drops, OCR/layout stability and zero-network Original/Translated toggles.

## 6. Next implementation step

Implement T1 first. Do not touch clipboard rail code, OCR geometry, media-resolution tuning or local translation rendering until the transport-only build has passed its regression check.
