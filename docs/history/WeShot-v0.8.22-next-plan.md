# WeShot v0.8.22 verification and next plan

This checkpoint supersedes the older v0.8.3 test-baseline section in `WeShot-implementation-plan.md` for current testing and implementation order.

## Verified current state

The current branch is `weshot-v0.8.8-ui`, with v0.8.22 built successfully by the normal Windows workflow.

Translation rendering has moved beyond the original flat-block baseline:

- Adjacent body lines can be recovered into paragraph-like regions before layout.
- Each translated region is treated as a hard layout slot derived from source geometry.
- Source visual text size is preserved when the translation fits; shrinking happens only when required.
- Overlapping slots are deterministically partitioned before drawing, so later blocks cannot paint over earlier translated text.
- DirectWrite layout is measured before drawing and a fit/collision audit is logged.
- Pixel-derived text geometry remains available as a fallback when OCR geometry misses thin/small text.
- Original pixels remain canonical; translated pixels are still rendered locally rather than generated by Gemini.

## Interaction contract

Keep the WeChat-like interaction stable while rendering is refined:

1. Capture selection remains fully interactive while OCR/translation is pending.
2. OCR side-panel controls own their mouse/keyboard gestures and never resize or drag the selection.
3. First Translate request may use Gemini; Original/Translation switching after success is local only.
4. Changing source pixels or the capture rectangle invalidates the derived OCR/translation revision.
5. A stale async result must never paint onto a newer selection.
6. Closing/reopening the OCR panel does not invalidate cached OCR or translation for the current revision.

## Immediate verification gate for v0.8.22

Do not add another layout heuristic until this build passes a fixed visual matrix. Test the same samples at 100%, 125%, and 150% Windows scaling:

- black text on white background;
- white text on a dark panel;
- multi-line English chat bubble translated to Simplified Chinese;
- two adjacent paragraphs with similar x-ranges;
- title + body + caption hierarchy;
- very small/thin UI text;
- mixed Chinese/English/numbers/punctuation;
- long screenshot with chat bubbles crossing a tile boundary.

For each sample record:

- missing/extra OCR regions;
- paragraph merges that are correct vs incorrect;
- collisions before/after constraint layout;
- fit failures;
- translated text that becomes unacceptably small;
- background damage around source glyph removal;
- first Gemini response time;
- whether Original/Translation toggle is instant and network-free.

## Next implementation order

### Gate 1 — Layout correctness before appearance

Refine v0.8.22 only when the test matrix exposes a reproducible failure. Priority fixes:

- Prevent false paragraph merges across separate chat bubbles/cards by requiring compatible background/role evidence in addition to geometry.
- Add a minimum readable font threshold. If a translation cannot fit without becoming unreadably small, prefer controlled vertical expansion inside available free space or a clearly logged fallback instead of microscopic text.
- Preserve left/center/right alignment from source geometry where it can be inferred reliably.
- Keep the deterministic no-overlap audit as a hard invariant.

### Gate 2 — Background reconstruction

Once layout is stable, improve the WeChat-like visual effect without changing text geometry:

- sample border strips around each text region rather than the glyph-filled interior;
- use median/trimmed-mean background estimation;
- detect inconsistent border strips and avoid painting a visibly wrong flat rectangle;
- add lightweight edge-aware/inpainting fallback for gradients, chat bubbles, and textured UI;
- estimate source foreground color instead of defaulting only to black/white.

### Gate 3 — Shared capture-scoped OCR/translation state

Toolbar Translate and OCR panel must use one revision-keyed cache and one in-flight request per `(revision, model, language)` tuple. This prevents duplicate image uploads and makes reopening the panel/toggling views free.

### Gate 4 — OCR panel isolation regression pass

Verify text selection, Ctrl+C, Original/Translation tabs, Retry, and Close cannot leak mouse/keyboard input into capture hit-testing. Panel focus changes must never mutate the capture revision.

### Gate 5 — Latency instrumentation

Keep local-only timing for PNG encode, request build, send, wait, read, parse, render, and total. Use this data before changing Gemini parameters again; do not diagnose Windows 12002 as a proxy failure without stage evidence.

### Gate 6 — Long screenshot translation

Use overlapping vertical tiles only when the image is too large for a safe single request. Remap coordinates to the full stitched image and deduplicate overlap regions. Saving/copying must always use the original full-resolution stitched pixels.

## Release rule

A new test build should be promoted only when CI succeeds and the fixed visual matrix has no new regression in selection interaction, OCR-panel isolation, local Original/Translation switching, or translated-region collisions.
